# BTC 5m 前向入场对照 v4

目的：验证旧 v3 的 checkpoint 回放优势，能否在未来新市场中重复出现。旧数据仅用于提出假设和逐笔审计，不作为新实验验证样本。本轮只改变入场时机，不拟合参数，不启用真实交易。

## 命令

先停止旧进程，更新代码。不修改 .env / pyproject.toml，不清空数据库。旧 `uv run jevymarket run` 和 `stats` 仍然是 v3；新实验使用明确独立入口：

```powershell
# 可选但建议先保存旧实验的逐笔证据。只导出白名单研究字段，不导出API Key、私钥、钱包、原始API响应。
uv run python -m jevymarket.entry_ab audit-v3 --out v3_entry_audit.json

# 一个进程、同一行情，两个独立模拟账户
uv run python -m jevymarket.entry_ab run --dry-run --loop 10

# 停止后查询、回填官方结果并导出新实验
uv run python -m jevymarket.entry_ab stats --out v4_entry_ab_report.json
```

输出文件不会被覆盖。再次导出请改名或使用带时间戳的名称。只离线查看时加 `--no-settle`。自定义实验名使用 `--experiment`，查询也必须传同名。默认新名称为 `v4-btc5m-entry-ab`，不允许使用 v2/v3 名称。

## 固定实验协议

- 仅 BTC 5m，目标10秒开始到开始的节拍，复用 v3 FastRunner、RTDS监听、数据门槛、读取预算和官方结算。新命令不构造可签名/可交易客户端，不提交真实订单。
- 连续组在任何有效10秒观察中寻找首次合格信号；checkpoint组只使用每个固定检查点的第一条有效记录。检查点保持 T-240/180/120/60/30，记录定义仍由 v3 决定，不向前/向后补造缺失记录。
- 两组在同一时刻收到同一份观察和盘口。Φ(Z)、edge、Kelly系数、价格区间、最小份数、仓位上限及已有安全门槛完全相同；只改变允许入场的时机。不同时间入场当然可能有不同方向、价格、金额。
- 两组各自每市场最多一单；各有独立但相同上限的未结算模拟敞口。连续组先入场不会占用 checkpoint 组的额度。模拟订单保存在新表 `entry_ab_orders`，不写入旧 v2/v3 订单表。独立账户仅为对照，不能合并理解为一份实盘资金的可用额度。
- 首次创建实验后从下一个完整5m窗口开始入场；等待期间照常监听/观察。重启不删除订单、不重新开始实验。共享 OS 文件锁阻止同一数据库启动两个 fast/entry_ab 进程。
- Jev继续只在checkpoint进行一次影子调用，两组共用，不影响入场、不重复请求，不新增 Laya 或其他模型。
- 首次复核点预先定为300个已结算有效市场。这个数是流程约束，不保证统计显著或盈利；不因短期盈利提前收工，也不在中间反复调阈值。严重工程错误可以暂停，需标注中断。

## 统计口径

新 stats 读取的是前向运行当时已经写入的两组订单，不是在结算后寻找入场机会。

报告包含：每组已结算/待定、赢单数、投入、毛PnL/ROI、相同订单按$1归一化的收益、剔除最大三笔获胜贡献后的敏感性检查；同一已结算有效市场的两组收益差；共同入场和相反方向数量；完整checkpoint子集的敏感性检查；覆盖率和实际节拍；概率评分及逐筆研究特征（JSON）。

主对照分母使用同一批有有效观察、已官方结算的市场。某组未交易在该市场记0；未结算订单不计入盈亏。没有有效数据的市场不冒充零收益样本，覆盖缺失需单独解释。完整checkpoint子集仅用于敏感性分析，不能因其表现更好而事后替换主样本。

2%/5%的成本扣减是按投入金额计算的假设压力情景，**不是Polymarket实际费率，更不是准确的净收益**。本版本仍未模拟真实手续费、滑点、队列、盘口深度成交或市场冲击。上线实盘前必须按具体市场核验费用和可成交性。$1是同一批已记录订单的归一化诊断，不代表允许突破交易所最小订单量。

旧 v3 JSON 用来逐笔核对原先连续入场与checkpoint回放的差异；它不含新 v4 样本。新JSON导出包含研究价格、概率、公开slug、市场结果、入场时间、金额和特征，不需要上传整个数据库或 .env。

## 判读

先看同市场的前向收益差是否持续，再检查贡献是否集中在少数便宜获胜订单、分时段稳定性、缺失样本偏差与执行成本。不能仅凭胜率或一个高毛ROI就推广。若新checkpoint优势消失，应保留结果，不反向在这批验证数据上寻找新阈值并声称验证成功。
