# BTC 5m：v6 临近结算 Maker 前向研究

版本：`v6-btc5m-late-maker-r1`。本入口只使用公共数据，只模拟；没有私钥、签名、真实下单或领取返佣接口。无需安装之前的 health ZIP。v2/v3/v4 的代码、数据库、参数和历史订单均不修改。

这是新策略假设，不是已经验证盈利的升级。旧 v4 数据没有逐笔队列和毫秒订单生命周期，不能用旧数据证明这个 Maker 策略的成交或收益。


## 实际入场与退出规则

1. 只处理当前 BTC 5m，Gamma 元数据必须明确 Up/Down、token 映射、结束时间、Chainlink 及 TWAP30/60规则；未知规则不默认60秒。
2. raw、TWAP30、TWAP60持续 WebSocket 接收，盘口也使用持久 market WebSocket 的完整快照和增量。REST只读取低频元数据、tick/最小份数、服务器时钟与官方结果，不用于2秒吃单报价。Jev/DeepSeek不进入低延迟执行链路。
3. 仅剩余 **2 < t <= 10秒** 时允许挂单；最后2秒撤单，不再新开。最后10秒只是时间资格，不自动代表高胜率。
4. 至少180秒完整 raw 历史、缺口不大于5秒、raw/TWAP源样本不旧于5秒。目标价只使用本地捕获的**精确源时间边界 TWAP**；启动中途漏过边界就等待后续市场，不猜目标价。盘口两边完整、新鲜，源与接收年龄均不超过1秒，点差不超过0.04。
5. 用“已进入最终结算窗口的 raw 积分 + 尚未发生部分的随机波动”估计最终 TWAP，而非旧的当前 TWAP 距目标 / sqrt(剩余时间)。同时比对同一源时刻重构 TWAP 与官方 TWAP，误差过大不挂。
6. 模型与盘口必须同向，所买方向两者概率均 >=0.92，差异 <=0.10。报价参考 `min(模型概率, 盘口归一化中价概率) - 0.005`，再至少留0.005 edge。它是保守启发式，不是校准完成的概率或统计置信下界。
7. 仅 BUY、GTC、post_only；买价不高于 best bid，并受公允价折扣、ask-tick和0.98上限约束，按tick向下取整。低于0.85不挂。**跨价拒绝，不转吃单，不靠返佣使负 edge 看起来变正。**
8. 默认报价TTL2秒；价格或风险条件变化即请求撤单。收到模拟撤单回执后才按新盘口重挂；最多8次报价尝试/市场、最短重挂间隔200ms。已有任何估计成交后不追加新订单、不反手；活跃单剩余部分仍可成交，已成交部分持有到官方结算。这不是双边库存做市或已实装的买卖往返套利。

## 小额风控与利润集中度

模拟资本500美元。单笔最大投入取 `min(5美元, 资本1%, 可用风险预算)`；同市场累计最多5美元，总风险占用最多50美元。最小份数会突破上限时跳过，绝不为了凑份数放大金额。

每市场最多一次有成交的订单，完整胜出时的毛利润上限0.50美元。该上限通过份数事前约束，不截断真实的记账收益。买价下限0.85并不保证可下单，例如最低5份且利润上限0.50时，一些低价候选仍会因最小份数被拒绝。

每天（UTC+8，按结算日期）毛亏损预算10美元，未结算仓位、在途挂单、在途撤单和断线未知部分按最大可能亏损占用预算；因此有效敞口可能比50美元更小。未知部分不记乐观盈利，必要时暂停直到官方结果可以确定最坏风险。不采用马丁格尔或亏损后翻倍。

“最大赢单占总净利润 <=2%”不能作为逐笔开仓硬条件：第一笔盈利占当时利润100%，净利润<=0时该比例无意义。统计同时给出最大赢单/净利润、最大赢单/所有正利润、去最大3笔正贡献后的盈亏；至少50个已结算有成交市场且净利润为正才标记集中度可评估。**2%是检验目标，不是保证。**更多计算/报价不等于更多独立交易机会。

## 模型假设与成交模型

令最新 raw 源时间为t，结束时间T，TWAP长度w，h=T-t。h<w时：

```
最终均值 = [积分(T-w到t的已知raw路径) + h*最新raw价] / w
未发生部分方差 = sigma^2*h^3/(3*w^2)
```

h>=w时采用零漂移布朗基线 `mean=spot, variance=sigma^2*(h-2w/3)`。sigma使用60/180秒美元波动率较大者，设置0.5美元/sqrt(s)下限并乘1.5压力倍率；再加入至少2美元、并随对齐误差增大的价格噪声。CDF概率截断到[0.005,0.995]。这些常数是显式研究设定，未用v4挑选赢单拟合，也不能声称最优；TWAP离散采样、跳跃和条件成交选择偏差仍可能使估计失准。

模拟提交与撤单单程延迟各默认100ms，属于**可变实验假设**。挂单到达后重检post-only，按当时同价及更优价可见队列排后。只有后续对应token的公开主动SELL成交打印才消耗队列和剩余份数；单纯盘口碰价、盘口量减少、主动BUY、重复打印都不算买单成交。支持部分成交以及撤单在途成交；缺少可观察数据或迟到打印导致结果不明时标记`uncertain`并占用风险，不把它当正常未成交释放资金。

公开逐笔打印不能证明自己的排队位置，也不保证捕获所有真实成交；相同打印去重还可能少计。因此统计明确叫“估计成交/估计盈亏”，不是真实收益或严格保守下界。重启保留已记录成交，未关闭单标记中断未知，不能重启洗掉风险。官方结算要求市场关闭及精确1/0，0.99/0.01不是结算。

## 2秒与100毫秒不是同一个保证

定期观察落盘和终端输出默认2秒；输入行情变化即时触发估值/风险检查，另有50ms看门狗检查TTL、过期和结束窗口。数据库批量写入独立线程，REST、Jev均不阻塞核心判断。

100ms指本地事件接收到生成动作的预算：实际超预算会取消报价并记录，导出给出本地反应p50/p95/p99与超过100ms次数。Windows调度、网络往返、服务器处理和交易所回执不在这个保证范围；`live_cancel_ack_ms`保持空值，没有用模拟100ms冒充实测。撤单重挂须顺序确认，绝不为了100ms数字提前释放未知挂单额度。CLOB秒级时间检查只排除较大偏差，不能代替专业时钟同步。

代码不依赖Taker还有某段保护延迟，按对手方可能立即成交处理。没有从官方材料核实“所有市场均已永久取消延迟”；不要将此说法写成已经证实的全市场规则。

## 费用、返佣和验证

基础报告Maker手续费按当前零费规则假设，返佣固定不计入；没有挂单即返佣或成交额固定返佣率。只模拟不会真的提供流动性或收到返佣。未来实盘接入必须另外完成签名、私有订单/成交回报、成交对账、心跳撤单、未知回执恢复与实际费用/返佣核验；本版本没有这些实盘功能。

交付前在Python3.13完成48项离线测试及编译检查；覆盖规则、盘口序列、源时钟、队列、部分成交、撤单竞态、重启、资金占用和数据库隔离。未在交付环境完成真实网络长跑、Windows验收或全仓库回归；不把离线测试当收益验证或真实100ms性能证明。

首次运行应先检查是否收到两侧盘口、raw/TWAP、精确边界与正常2秒输出，再积累新市场。没有符合全部条件或没有真实成交打印时，零成交是允许的，不为提高成交数关闭保护。新旧收益不能混在一起。
