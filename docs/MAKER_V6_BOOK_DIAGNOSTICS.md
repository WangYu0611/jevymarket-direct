# v6-io-r3：盘口恢复及小型诊断

基于 main `a7e2b21`。保留原 MakerConfig、概率、入场时间（2<t<=10秒）、单笔金额、post-only、估计成交与官方结算规则。旧 v4 和现有数据库不删除、不迁移。仍然只有模拟，没有真实订单接口。

## 策略范围澄清

原规则不是“最后2秒才买”：是2<t<=10秒允许报价，t<=2秒进入撤单区。
这两个时间参数都没有被证明最优。用户已明确质疑过晚入场；本次不把该窗口当作已成立的策略优势，也不直接改成更早秒数来制造成交。
新增 `--observe-only` 仅观察模式，即使旧策略候选完全符合，也禁止生成新模拟挂单；已有历史订单/风险保留。运行标记及观察均保存该模式。
建议以下验收使用独立诊断数据库，不与收益试验混样。较早Maker窗口和撤单安全余量，另以新实验验证；不改旧库的历史规则。

## 本次完成与未完成

- 修复缓存失效后仍保留旧代次时间戳的问题。新订阅必须等完整快照，但不再把已丢弃代次的时间戳强加给新基线；同一代次的乱序检查、5秒接收检查与1秒报价新鲜度都保留。这不证明所有历史乱序都由该问题造成。
- 所有盘口更新先在副本中校验，全部成功才更新交易缓存。失败时先保存更新前与候选状态，再使交易缓存失效。
- 失败帧保存为 `book_reject`，包括原消息的白名单字段、接收时钟、会话ID、更新前/候选盘口。失败不冒充成功 `book_event`；不因为记录失败而绕过校验。长字段/数组、非有限数有明确的诊断清洗标记，不保存HTTP头、任意错误体、凭证。
- 每2秒状态区分“待快照”“缓存失效”“新鲜仅买盘/仅卖盘”“新鲜空盘”“源时间过期”“接收时间过期”“双边就绪”。正常单边盘口不再被描述为断线，但仍不放行本策略；不以1.0补出不存在的卖价。
- 每次本地合并信号至动作的耗时均累积到 `reaction_window` 直方图，不要求已有订单；定时检查耗时单列。每2秒批量落盘，避免给每个事件增加一条延迟日志。0.1ms桶给出分位数上界近似，超过10秒的桶以上界最大值显示。它不是WS逐帧时延、网络传输或交易所回执保证。旧 `stats.local_reaction_ms` 仍保留旧抽样口径，新的完整口径由 `diagnose` 输出。
- **尚未确认历史149次BBO不一致的同一根因**：旧导出没有失败帧。本次保留原BBO检查语义，不将删掉检查或猜测批次语义当修复。
- **未调整入场窗口/92%门槛/价格上限**，更早Maker窗口与单边盘口报价须独立实验，不能因零报价直接调低标准。

## 本地操作（PowerShell）

先Ctrl+C停止旧采集，等它退出。不要强退、删库、还原本地uv.lock或上传.env。

```powershell
cd C:\Users\wy331\Documents\jevymarket-direct
git pull --ff-only
uv sync --frozen
uv run --frozen python -m pytest tests/test_maker_v6.py tests/test_maker_protocol.py tests/test_maker_book_diagnostics.py -q
```

每步失败就停止处理错误，不能无视失败继续启动。启动行应包含 `v6-io-r3` 和“仅观察模式”。本次运行有边界的900秒连接/诊断验收，不执行有争议的末段入场，不是等待盈利的长跑：

```powershell
uv run --frozen python -m jevymarket.maker run --dry-run --observe-only --loop 2 --seconds 900 --db jevymarket.maker-v6-io-r3-check.db
```

程序在运行满900秒后按正常停机路径退出。启动仍需180秒完整参考历史及后续精确边界；该模式不会生成任何新模拟报价，空白诊断数据库下报价与成交应为0。主要验收：拒绝帧是否有证据，错误是否仍频繁发生，缺盘口原因能否区分，无订单时延迟统计是否有样本。正收益不是验收条件。

退出后（或另一个终端运行中）只读导出小型诊断：

```powershell
uv run --frozen python -m jevymarket.maker diagnose --db jevymarket.maker-v6-io-r3-check.db --out "v6_book_diag_$(Get-Date -Format yyyyMMdd_HHmmss).json.gz"
```

`diagnose`不联网、不结算、不修改或初始化源数据库。统计范围为数据库中最近一个 `runtime` 标记之后；订单总数明确为全库累计。它只读诊断类型事件，不解析/复制全部盘口流。导出每原因最多2个失败样例，总计最多6例、原始样例内容不超过2MB；另保留最后24条入场时段观察和最新状态。被省略的案例给出数量，完整证据仍在原数据库，必要时才用原 `maker stats --out ...json.gz` 导出。

使用自定义 `--db` 时，run/diagnose/stats/settle均传同一个路径。输出文件不会覆盖。旧记录保持原样，新启动和观察记录带 `v6-io-r3` 与会话ID。无需再传之前的60MB导出。
