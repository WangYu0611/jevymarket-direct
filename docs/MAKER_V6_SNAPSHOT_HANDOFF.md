# v6-io-r4：快照交接与关闭连接前的风控

基于 `77fd13d`。仍是只模拟、仅观察验收阶段；本次不调整 MakerConfig、概率模型、入场时间、价格、金额、成交估计或结算规则。`maker_book.BookCache` 的原始严格校验器保持不变。

## 证据与边界

指定旧会话的有界上下文包含 5810 条事件，其中 5759 条成功盘口事件、11 条拒绝、11 条源错误、28 条观察、1 条市场登记。它不是完整900秒流，也不是新的采集。上下文中11次拒绝均能从先前完整快照及已存增量复现；4个原诊断焦点的失败前深度、源时间和ready状态与原诊断吻合。

其中7次是BBO不一致：单条增量未删除的历史价位与该消息报告的BBO冲突。4次是刚收到完整快照后又收到更早增量，3次早1ms，另1次早15/16ms。旧增量可能与快照数量相同，也可能不同，不能强行应用来消除异常。

**本修订不宣称已修复7次BBO冲突的根因，更不宣称修复全部历史73/149次BBO错误。** 旧连接在拒绝后关闭，未记录的后续消息及WS帧边界无法事后补回。公共文档区分快照、增量和成交事件，不提供这些历史事件缺失的因果证据。没有以推测删除价位、以最优价替代完整深度，或取消BBO检查。

## 两项修复

### 1. 快照基线前的启动增量：只丢弃，不应用

运行入口使用 `SnapshotBookCache` 包装严格缓存。只有所有变更行均对应已订阅token、每个token刚接受了完整快照且尚未接受该快照之后的增量、消息源时间严格早于所有相关快照，以及消息和快照仍在原接收时效内，才记录 `book_discard / pre_snapshot_delta_discarded` 并跳过整条旧增量。

丢弃不会改变任何价位、数量、代次、排序水位、源时间或接收时间；不计为成功 `book_event`，不会生成成交。不是允许任意1ms乱序，也不是调整消息时间。相等时间戳仍按原规则处理；部分token旧、部分token新不会部分丢弃；接受新增量之后再乱序仍拒绝。缺快照、过期、超前、畸形、BBO不一致及交叉盘口保护保持。

`diagnose.summary.event_counts_latest_run.book_discard` 可查看最近运行的丢弃数量；详细白名单证据保留在原数据库。旧历史记录不改写，不删除或迁移数据库。

### 2. 风控先于连接关闭等待

订阅、收取、解析或应用盘口发生异常时，在心跳任务清理和WebSocket退出等待之前，立即使缓存失效、发起本地模拟撤单，并按既有规则保留活跃订单的未知成交风险。连接关闭和后续退避不能挡在这条本地风险路径之前。

旧日志中拒绝记录到外层source_error大多约2秒，与原代码的上下文退出顺序一致。但其他信号/定时检查可能更早触发风险动作，且该会话没有订单。因此这不是“真实撤单曾经耗时2秒”的测量，也不是修订后的100ms实盘回执证明。
